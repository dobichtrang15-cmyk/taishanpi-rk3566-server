# 项目背景

## 1. 项目要解决的问题

这套系统的起点是一块立创·泰山派 RK3566 开发板。开发板功耗低、可以持续运行，但计算能力和桌面软件生态有限；Windows 工作站性能强，但没有必要全天开机。

项目因此采用“常在线控制节点 + 按需启动工作站”的分工：

- 泰山派负责文件入口、同步、远程连接、状态检测和自动化。
- Windows 工作站负责需要较高性能或 Windows 环境的任务。
- 开发板通过有线直连网络向 Windows 发送 WOL 魔术包。
- Windows 开机后通过 OpenSSH 接收受控的关机命令。

这个方案不需要继电器，不接触电脑主板电源针脚，也不会模拟长按电源键。开机和关机都复用标准网络能力。

## 2. 项目演进

### 阶段一：开发板基础服务器

最初目标是让 RK3566 提供网页文件访问，并将 `/userdata` 作为主要数据盘。该阶段形成 Flask 后端、Nginx 入口和基础 systemd 服务。

### 阶段二：文件与同步管理

项目加入文件上传、下载、目录操作、预览和 Syncthing 状态管理，用于在开发板、Windows 和个人知识库之间同步数据。

### 阶段三：本地控制台

开发板连接 HDMI 小屏，浏览器以 kiosk 模式自动打开本地面板。另保留 Qt 原型，便于比较 Web kiosk 与原生界面的维护成本。

### 阶段四：工作站电源管理

开发板 `eth0` 与 Windows 有线网卡直连，形成独立的 `192.168.50.0/24` 控制网络：

- 在线检测：测试 Windows SSH 端口是否可连接。
- 开机：发送 Wake-on-LAN 魔术包。
- 关机：通过 SSH 执行 `shutdown /s /f /t 0`。

这种设计与家庭 Wi-Fi 分离。即使家庭路由器更换，只要开发板和 Windows 之间的网线、固定地址和 WOL 设置不变，电源控制仍可工作。

### 阶段五：多端访问

Web 控制台之外，项目增加微信小程序，并预留 Cloudflare Tunnel 和反向 SSH 作为公网接入方式。公网域名只负责 HTTPS 应用流量，不能直接替代苹果家庭中枢。

### 阶段六：Matter 接入

`apps/matter-workstation` 使用 matter.js 将现有 WOL/SSH API 暴露为 Matter 插座：

- Matter `On` 调用 `/api/device/workstation/wake`。
- Matter `Off` 调用 `/api/device/workstation/shutdown`。
- 插座状态通过 `/api/device/workstation/status` 定时同步。

Matter 层不重复实现 WOL 或 SSH，只作为协议适配器。这使业务逻辑集中在 Flask 后端，降低后期维护成本。

## 3. 当前实际部署基线

最早运行环境为：

- 硬件：立创·泰山派 RK3566
- 系统：Ubuntu 20.04 ARM64 定制镜像
- 数据根目录：`/userdata`
- 应用目录：`/userdata/server`
- 文件目录：`/userdata/files`
- 开发板直连口：`192.168.50.1/24`
- Windows 直连口：`192.168.50.2/24`
- Web 入口：Nginx 80 端口
- 后端：Flask 5000 端口，仅由本机 Nginx 和 Matter 服务访问
- Matter：UDP 5540，mDNS UDP 5353

仓库现在通过 `/opt/taishanpi-server` 和 `/srv/taishanpi-files` 两个稳定软链接隔离物理存储路径。其他设备可以把实际数据放到 `/mnt`、`/srv` 或其他磁盘，而无需修改服务文件。

## 4. 核心设计决策

### 单一业务 API

Web、微信小程序、HDMI kiosk 和 Matter 都调用同一个 Flask API。开关机逻辑只维护一份。

### 私有配置与源码分离

用户、密码哈希、设备 MAC、SSH 信息、Token、Matter Fabric 和隧道凭据都保留在运行设备上。Git 只保存示例和配置模板。

### systemd 管理进程

Nginx、Flask、Matter 和直连网卡配置都由 systemd 管理，具备开机启动、失败重启和统一日志入口。

### 本地控制与远程入口分离

Matter 面向局域网控制器；HTTPS 域名面向互联网。两者可以同时存在，但安全模型不同，不应把 Matter 端口直接映射到公网。

### 保留低耦合的前端

Web UI 当前是静态 HTML/JavaScript，部署成本低。微信小程序和 Qt 原型独立存放，不要求所有客户端使用同一构建工具。

## 5. 项目边界

项目负责：

- 开发板服务部署和运行。
- 文件、同步和设备控制 API。
- Windows WOL 与 SSH 关机编排。
- Matter 协议桥接。
- 本地和远程客户端入口。

项目不负责：

- 替代 HomePod 或 Apple TV 成为苹果官方家庭中枢。
- 将 Matter UDP 端口直接暴露到互联网。
- 自动修改 Windows BIOS、网卡驱动和防火墙。
- 把真实凭据或运行态存入 Git。
- 提供无备份的数据恢复保证。

## 6. 已知约束

- 定制 Ubuntu 20.04 镜像可能存在 APT 源版本不一致或软件包 hold，安装脚本提供 `SKIP_APT=1` 供已手工安装依赖的环境使用。
- matter.js 0.17.3 需要 Node.js 22.13 或更高版本。
- Matter over IP 依赖局域网 IPv6 链路本地地址和 mDNS；路由器的访客隔离、AP 隔离会导致 Apple“家庭”显示无响应。
- 没有苹果家庭中枢时，iPhone 离开家庭局域网后不能依靠 Apple“家庭”稳定远程控制；应使用 HTTPS 域名、微信小程序或快捷指令。
- 密码方式的 Windows SSH 需要 Paramiko；更推荐使用受限 SSH 密钥。

## 7. 可维护性目标

后续改动应保持以下约束：

1. WOL/SSH 逻辑继续集中在 Flask 后端。
2. 客户端只调用公开 API，不直接读取运行态文件。
3. 新配置必须支持环境变量或外部配置文件，不能新增机器专属硬编码。
4. 安装脚本必须可重复执行，并保护已有 `users.json`、`devices.json` 和 Matter Fabric。
5. 发布前必须通过项目验证脚本和 GitHub Actions。
6. 对外接口变化需要同步更新文档和变更记录。

## 8. 后续建议

优先级较高的演进方向：

- 为公网开关机接口增加短期 Token、速率限制和审计日志。
- 将 Flask 开发服务器替换为 Gunicorn 或 Waitress 类生产 WSGI 服务。
- 为后端拆分模块并补单元测试。
- 为备份脚本增加 Matter Fabric 和恢复流程。
- 将 Nginx 域名/TLS 配置做成独立模板。
- 对微信小程序的 API 基地址提供构建时配置，而不是源码常量。
