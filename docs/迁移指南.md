# 迁移指南

## 1. 迁移目标

本指南覆盖三种场景：

1. 同一块开发板更换系统或磁盘。
2. 从泰山派迁移到其他 ARM64/x86_64 Linux 主机。
3. 新建测试环境，不导入旧运行态。

源码可以直接从 GitHub 克隆；私有配置和运行数据必须通过独立备份迁移。

## 2. 迁移前清单

记录旧设备：

```bash
uname -a
cat /etc/os-release
python3 --version
node --version
nginx -v
ip -br addr
systemctl list-unit-files | grep -E 'filemgr|matter-workstation|eth0-direct'
```

检查服务：

```bash
sudo systemctl status nginx filemgr matter-workstation eth0-direct --no-pager
```

生成配置备份：

```bash
sudo bash ./deploy/backup.sh
```

此外单独备份：

```text
/userdata/files 或当前 FILEMGR_ROOT
/var/lib/matter-workstation
Syncthing 数据目录和配置
/etc/default/filemgr
/etc/default/matter-workstation
/etc/default/eth0-direct
Cloudflare Tunnel 凭据
SSH 私钥
```

备份包含凭据，必须加密传输和保存，不能上传 GitHub。

## 3. 新主机准备

最低要求：

- systemd
- Python 3.8+
- Nginx
- Git
- Node.js 22.13+（使用 Matter）
- 可用的固定数据目录

若目标是无显示器服务器，使用 `INSTALL_KIOSK=0`，可避免安装桌面和浏览器依赖。

## 4. 全新安装

```bash
git clone https://github.com/dobichtrang15-cmyk/taishanpi-rk3566-server.git
cd taishanpi-rk3566-server
sudo INSTALL_KIOSK=0 bash ./deploy/install.sh
```

选择其他磁盘：

```bash
sudo \
  TAISHANPI_INSTALL_ROOT=/mnt/storage/taishanpi-server \
  TAISHANPI_FILES_ROOT=/mnt/storage/files \
  INSTALL_KIOSK=0 \
  bash ./deploy/install.sh
```

安装脚本创建稳定软链接：

```bash
readlink -f /opt/taishanpi-server
readlink -f /srv/taishanpi-files
```

## 5. 恢复私有配置

恢复前停止服务：

```bash
sudo systemctl stop matter-workstation filemgr
```

恢复下列文件到新应用目录：

```text
users.json
devices.json
secret.key
```

`tokens.json` 可以不恢复，让所有客户端重新登录更安全。

权限建议：

```bash
sudo chmod 600 \
  /opt/taishanpi-server/apps/filemgr/users.json \
  /opt/taishanpi-server/apps/filemgr/devices.json \
  /opt/taishanpi-server/apps/filemgr/secret.key
```

恢复 Matter Fabric：

```text
旧机 /var/lib/matter-workstation/*
新机 /var/lib/matter-workstation/*
```

然后：

```bash
sudo chown -R matter-workstation:matter-workstation /var/lib/matter-workstation
sudo systemctl start filemgr matter-workstation
```

如果没有恢复 Matter Fabric，必须在 Apple“家庭”中删除旧设备并重新配对。

## 6. 调整网卡和地址

修改：

```bash
sudo nano /etc/default/eth0-direct
```

示例：

```text
DIRECT_INTERFACE=enp2s0
DIRECT_ADDRESS=192.168.50.1/24
```

应用：

```bash
sudo systemctl daemon-reload
sudo systemctl restart eth0-direct
ip -br addr
```

再在 Web 管理页面更新 Windows IP、MAC、广播地址和 SSH 信息。

## 7. 调整 Syncthing

修改 `/etc/default/filemgr`：

```text
SYNCTHING_USER=实际Linux用户
SYNCTHING_SERVICE=syncthing@实际Linux用户
SYNCTHING_GUI_URL=http://开发板地址:8384
SYNCTHING_FOLDER_PATH=/srv/taishanpi-files/obsidian-vault
```

重启：

```bash
sudo systemctl restart filemgr
```

## 8. 定制 Ubuntu 20.04 的 APT 问题

若镜像存在 held packages、源版本不一致，但 Python、Nginx、Node.js 和浏览器已经手工安装，可执行：

```bash
sudo SKIP_APT=1 bash ./deploy/install.sh
```

如果脚本报告依赖缺失，应先修复对应依赖，不要执行 `full-upgrade` 或无差别解除全部 hold。

## 9. 验证迁移结果

```bash
sudo systemctl status nginx filemgr eth0-direct matter-workstation --no-pager -l
curl -fsS http://127.0.0.1:5000/api/device/workstation/status
curl -I http://127.0.0.1/
sudo journalctl -u filemgr -n 100 --no-pager
sudo journalctl -u matter-workstation -n 100 --no-pager -l
```

功能检查：

- Web 登录和文件列表。
- 上传、下载和预览。
- Syncthing 状态。
- Windows 在线检测。
- WOL 开机。
- SSH 关机。
- Matter 控制和状态同步。
- 外网域名和微信小程序。
- HDMI kiosk（如果启用）。

## 10. 回滚策略

升级或迁移前：

1. 记录当前 Git commit。
2. 运行私有配置备份。
3. 保留旧系统或旧数据盘，直到新系统完成验证。

代码回滚应使用明确的 Git commit，并重新运行安装脚本。不要删除运行态配置，也不要清空 `/var/lib/matter-workstation`。

## 11. 可移植性矩阵

| 能力 | ARM64 | x86_64 | 无桌面 | 非 `/userdata` |
| --- | --- | --- | --- | --- |
| Flask/Nginx | 支持 | 支持 | 支持 | 支持 |
| WOL/SSH | 支持 | 支持 | 支持 | 支持 |
| Matter | Node.js 22 可用时支持 | 支持 | 支持 | 支持 |
| HDMI kiosk | 有兼容桌面时支持 | 支持 | 不适用 | 支持 |
| 微信小程序 | 与服务器架构无关 | 与服务器架构无关 | 支持 | 支持 |

非 Debian 系发行版需要手工安装依赖，并使用 `SKIP_APT=1`。
