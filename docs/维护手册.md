# 维护手册

这份文档只解决一件事：以后回来看这个项目时，能快速知道该改哪里、怎么发版、怎么排障。

## 1. 目录职责

- `apps/filemgr/`
  Flask 后端主程序，认证、文件、设备、同步控制都在这里。
- `apps/matter-workstation/`
  Matter 插座桥，将 On/Off 指令转换为工作站 API。
- `www/`
  Web 页面和本地 HDMI 页面。
- `miniapp/`
  微信小程序。
- `deploy/`
  服务器安装与更新入口。
- `qt/`
  本地 Qt 面板实验版本。
- `scripts/`
  本地辅助脚本和打包脚本。

## 2. 关键入口文件

- 后端主入口：
  `apps/filemgr/app.py`
- 网页主界面：
  `www/site/index.html`
- 本地 HDMI 面板：
  `www/kiosk.html`
- 小程序请求入口：
  `miniapp/utils/request.js`
- 小程序登录页：
  `miniapp/pages/login/`
- 小程序总览页：
  `miniapp/pages/overview/`
- 安装脚本：
  `deploy/install.sh`
- 更新脚本：
  `deploy/update.sh`
- Matter 入口：
  `apps/matter-workstation/src/index.mjs`
- 运行环境模板：
  `deploy/filemgr.env`、`deploy/matter-workstation.env`、`deploy/eth0-direct.env`

## 3. 当前已知架构

- 开发板本机运行 Flask 后端
- Nginx 对外提供网页和反向代理 API
- 小程序直接访问线上域名
- 本地 HDMI 小屏访问本机页面
- 云服务器承担 OpenClaw / 远程入口 / 反向 SSH 中转
- Windows 工作站由开发板侧进行状态探测、WOL、SSH 关机控制
- Apple“家庭”等控制器通过 Matter 调用同一套工作站 API

## 4. 修改时的落点

如果你要改：

- 登录逻辑：改 `apps/filemgr/app.py` 和 `miniapp/utils/auth.js`
- API 域名：改 `miniapp/utils/request.js`
- 小程序页面样式：改对应页面目录下的 `.wxml` 和 `.wxss`
- Web 仪表盘布局：改 `www/site/index.html`
- HDMI 掉线/本地鉴权：重点看 `apps/filemgr/app.py` 里的本地 kiosk 信任逻辑
- 部署行为：改 `deploy/install.sh`、`deploy/update.sh`
- Matter 行为：改 `apps/matter-workstation/src/index.mjs`
- 文件根目录和 Syncthing 用户：改 `/etc/default/filemgr`
- 直连网卡和地址：改 `/etc/default/eth0-direct`

## 5. 发版前检查

1. 检查 `.gitignore` 是否排除了真实凭据和运行态文件
2. 检查 `apps/filemgr/users.example.json`、`devices.example.json` 是否还是示例数据
3. 检查 `miniapp/project.private.config.json` 没有被打包
4. 检查 `miniapp/utils/request.js` 的域名是否正确
5. 检查 `deploy/post-install.md` 是否仍然适配当前部署流程
6. 运行 `scripts/validate-project.ps1`
7. 更新 `CHANGELOG.md`

## 6. 常见故障排查

### 小程序真机登录失败

优先看这几个点：

- 微信后台是否配置了 request 合法域名
- `BASE_URL` 是否是 HTTPS
- 域名是否和小程序后台白名单完全一致
- 后端接口是否返回 200

### 本地 HDMI 全部显示掉线

优先看：

- `filemgr.service` 是否正常
- `www/kiosk.html` 是否能本机打开
- 本地 kiosk 请求是否被后端当成未登录请求拦截

### 云端连不上开发板

优先看：

- 开发板是否在线
- 反向 SSH 隧道是否还在
- 云服务器上的入口脚本是否仍指向正确端口

### Apple“家庭”显示无响应

优先看：

- `matter-workstation.service` 是否运行
- UDP 5353 和 5540 是否监听
- iPhone/家庭中枢与开发板是否处于可互访局域网
- 路由器是否启用 AP/访客隔离
- `/var/lib/matter-workstation` 是否被误删

```bash
sudo systemctl status matter-workstation --no-pager -l
sudo journalctl -u matter-workstation -n 200 --no-pager -l
sudo ss -lunp | grep -E '5353|5540'
```

### APT 依赖冲突

定制 Ubuntu 镜像已有依赖时，使用：

```bash
sudo SKIP_APT=1 bash ./deploy/install.sh
```

不要为了部署本项目直接执行无差别 `full-upgrade` 或解除全部 held packages。

## 7. 建议维护节奏

- 每次做完一组功能后，先跑一次打包脚本
- 每次改完接口或部署逻辑，就顺手更新这份维护手册
- 每次把项目迁移到新机器前，先保留一个 zip 归档
- 每次操作 Matter 配对状态前，先备份 `/var/lib/matter-workstation`
